# Schedule Reminder — Android Native + Rust Core

Android version of Schedule Reminder. **Android UI: Kotlin/Jetpack Compose; task/state/time/database core: Rust + UniFFI; local notifications: AlarmManager.** Runs on Android 8.0+ (API 26), including arm64-v8a, armeabi-v7a and x86_64. User-facing screens are in Vietnamese.

## Easiest build without an Android development PC: GitHub Actions (free on public repos)

1. Create a GitHub repository (prefer **Private** only if your plan has enough Actions minutes). Upload **all contents** of this project, including `.github/workflows/build-apk.yml`. The file is inside a hidden `.github` folder: upload using GitHub Desktop or Git with hidden files enabled.
2. In the repo click **Actions → Build Schedule Reminder Android APK → Run workflow**. Wait for the green checkmark.
3. Open that workflow run → **Artifacts** → `ScheduleReminder-Android-APK` → download ZIP and extract `ScheduleReminder-Android.apk`. Transfer APK to Android phone, open it and approve *Install unknown apps* for the file-manager/browser when prompted.

There is **no Apple account, Xcode, TestFlight, or certificate** for Android. The APK is a debug build signed automatically by Android Gradle tooling. It is appropriate for personal testing, not a Play Store release. Every fresh GitHub hosted runner can generate a different debug signing key: upgrading an existing installation may then require uninstalling it and may erase app data. Back up your reminders first.

## Windows 11 build without GitHub

Install Android Studio from https://developer.android.com/studio and its **SDK Platform 35**, **NDK (Side by side) 27.2.12479018**, and Android SDK Build-Tools 35.0.0. Install Rust using https://rustup.rs/ and reopen Command Prompt. Double-click `BUILD_APK_WINDOWS.bat`. It installs Rust targets / cargo-ndk and Gradle 8.13 on first run, builds native libraries and bindings, and creates `ScheduleReminder-Android.apk` in the project root. You will need Internet and enough disk space for SDK/NDK/Gradle/Rust dependencies.

To work in Android Studio, open the `android/` directory **after running the build script**, or generate a Gradle wrapper using locally installed Gradle. CI does not require any local Gradle wrapper.

## What works

- Add/list/update/delete/complete tasks, with notes and deadline.
- Rust owns SQL state and validation; the UI never reads or writes SQLite directly.
- `Mutex<Connection>` + SQLite WAL; SQLite bundled for Android ABIs.
- IANA zone/DST validation; one-off reminders are stored as UTC instants, so travel does not shift firing time.
- On-device alarms even when the UI is not running; alarms rescheduled after restart, clock/time zone changes, package replace, or alarm permission changes.
- User-configurable notification permission (Android 13+) and **Alarms & reminders** permission (Android 12+). If exact-alarm permission is denied, the app falls back to a potentially late inexact alarm. Doze and vendor battery restrictions can delay delivery.
- The app schedules the 128 nearest upcoming tasks to limit system alarm usage. Past/complete tasks remain in SQLite, but do not schedule future alarms.
- No account, ads, analytics, internet permission or remote service.

## Production notes

The debug APK, source project, and CI workflow are provided, **not a pre-built APK**. A successful end-to-end CI/physical-device build has not been validated in this runtime (Rust/Android SDK/Gradle network unavailable here). Android Compose/JNA resource usage is **not guaranteed <20 MB**; test with Android Studio Profiler/LeakCanary, and add automated UI/instrumented tests before production. Consider app-specific backup/export before rebuilding/reinstalling different debug signatures.

### Technical provenance

- UniFFI binding code generated from compiled Rust `cdylib` (`uniffi-bindgen` Kotlin + JNA AAR).
- AGP 8.13.2 with Gradle 8.13; Kotlin and Compose compiler 2.3.0; JDK 17.
- Rust core originally written for the iOS version and reused in Android without replacing the SQLite/time business logic with Kotlin.
